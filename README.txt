The current experience contains 51 sequential story scenes, indexed in the HTML and JavaScript from data-scene="0" through data-scene="50". Older chapter labels retained in the historical notes below are descriptive labels, not HTML data-scene indices.

HOW TO OPEN
1. Extract the ZIP file.
2. Keep index.html, style.css, script.js, poems.html, poems.js, poems-data.js, poem-page.css, poem-collection.css, let-you-know.html and the assets folder together.
3. Open index.html in a current version of Chrome, Edge, Firefox or Safari.

INTERACTION
- The story plays automatically and has no visible player interface.
- Tap or click anywhere to pause and reveal the three transport controls: Restart current scene (click again for previous scene), Play/Pause, and Complete current scene (click again for next scene).
- While paused, tap outside the controls to resume and hide them.
- Previous and Next navigation remains paused; the first press restarts/completes the current scene and a second consecutive press moves to the adjacent scene.
- The final story scene (the 51st scene, data-scene="50" — The Final Wish) remains on screen after the story ends. Tap to reveal controls; Play starts the story again.
- Keyboard: Space pauses/resumes; Left/Right arrows navigate while paused; Escape resumes.

GLOBAL NARRATIVE TIMING
- Ordinary narrative paragraphs appear one at a time, in their authored order.
- The waiting time after each line is 0.3 seconds multiplied by the number of words in that line.
- Previously revealed lines remain visible as later lines appear.
- After the final line has completed its own interval, the section remains visible for an additional 0.15 seconds multiplied by the total number of words across the section's narrative lines.
- Visual line wrapping does not affect the count. Each authored paragraph is counted as one line.
- In the two-column closing reflection, the memory list and reflection reveal in parallel; the final hold uses the combined word count of both columns.
- Pausing freezes both line reveals and all countdowns. Resume continues from the exact elapsed point.

MOBILE SCREEN WAKE LOCK
-----------------------
The experience requests the browser Screen Wake Lock API while the story is
active, so supported mobile browsers can keep the display awake during playback
and while paused. If the browser suspends the page, the site pauses playback and
requests a fresh wake lock when the visitor returns; it does not auto-resume.
The wake lock is released when the story finishes or the page is left.

The Screen Wake Lock API requires a secure context (normally HTTPS) and a
supporting browser. It can still be denied by battery saver / low-power mode or
operating-system policy. For the most reliable mobile behaviour, serve this site
from an HTTPS host (for example, GitHub Pages) and open it in the phone's browser,
not inside an embedded file-preview app. If the feature is unavailable or denied,
the site still plays normally, but the phone's regular screen timeout applies.

REDUCED-MOTION ACCESSIBILITY
---------------------------
The experience follows the operating-system `prefers-reduced-motion` setting.
When reduced motion is enabled, each scene's text and photographs are shown in
their settled state without typewriter reveals, staggered entrances, pop/scale
effects, route tracing, looping frame animation, or continuously interpolated
background lighting. Scene durations are retained so there is still time to
read each scene. The preference is also observed if it changes while the page is open.

PREVIOUS / NEXT NAVIGATION
